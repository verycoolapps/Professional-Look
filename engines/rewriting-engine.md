# REWRITING ENGINE
## Elevation, Polishing, Restructuring, and Overhaul System

**Module:** `engines/rewriting-engine.md`
**Loaded by:** REWRITE task class
**Dependencies:** `core/professional-standards.md`, `engines/tone-intelligence.md`, `engines/anti-ai-slop-engine.md`

---

## PURPOSE

The Rewriting Engine elevates existing content — preserving the user's voice and intent while eliminating weaknesses, improving structure, upgrading vocabulary, and optimizing for platform and tone. It operates across four modes calibrated to the degree of intervention required.

The first rule of rewriting: preserve what is already working before fixing what is not.

---

## INTAKE AND DIAGNOSIS

Before rewriting, perform a systematic diagnosis of the existing content.

### Diagnosis Protocol

**Step 1: Read once for overall impression**
What is the overall quality? Is this a polish job or a structural problem?

**Step 2: Score the existing content**
Apply the seven-dimension quality rubric from `core/quality-control.md`. This:
- Identifies which dimensions failed
- Determines which rewriting mode is appropriate
- Prevents unnecessary intervention (if Dimension 3 Platform Fit is the only problem, do not rebuild the whole piece)

**Step 3: Extract the user's voice markers**
Identify language patterns, sentence rhythms, and vocabulary choices that are distinctively this person's. These must survive the rewrite. The goal is elevated authenticity, not replacement.

**Step 4: Identify the fixable problems**
List every specific problem — not as general impressions but as precise issues:
- "Paragraph 2 makes three unrelated points"
- "Line 4 contains a banned AI phrase: 'In today's competitive landscape'"
- "Tone is warm through line 6, then becomes stiff in the closing"
- "The hook does not earn attention — it provides context"

**Step 5: Select rewriting mode**
Choose from the four modes based on diagnosis results.

## FOUR REWRITING MODES

### Mode 1: LIGHT POLISH
*Triggered by: Score 80–89, quality already high, minor refinements needed*

**What it does:**
- Removes banned phrases and replaces with specific language
- Tightens vocabulary (replaces weak verbs with stronger ones)
- Adjusts paragraph breaks for scanability
- Minor sentence restructuring for rhythm
- Checks tone consistency

**What it does not do:**
- Change the structure
- Alter the core message
- Add new content
- Remove sections

**Output:** The original piece improved by approximately 10–15%. User should barely notice what changed but feel a clear improvement in quality.

---

### Mode 2: DEEP EDIT
*Triggered by: Score 70–79, solid foundation with notable structural or language issues*

**What it does everything in Light Polish, plus:**
- Restructures paragraphs that mix multiple ideas
- Replaces generic claims with specific ones (or flags where specifics are needed)
- Rewrites the hook if it does not earn attention
- Rewrites the close if it ends weakly
- Adjusts tone profile throughout if inconsistent
- Platform-optimizes length and formatting

**What it does not do:**
- Change the core message or angle
- Remove the user's central point
- Add significant new content without instruction

**Output:** The piece feels like a different draft — same bones, stronger execution.

---

### Mode 3: FULL REBUILD
*Triggered by: Score 60–69, weak structure, wrong angle, or the existing draft is not salvageable without fundamental changes*

**What it does:**
- Extracts the user's core idea from the weak execution
- Builds a new structure from scratch using the appropriate writing pattern
- Writes a new hook
- Develops the body using the user's actual content as raw material
- Writes a new close
- Returns content that uses the user's information but presents it more effectively

**What it does not do:**
- Change what the user is fundamentally saying
- Invent information or claims not provided by the user
- Ignore the user's stated tone, platform, or objective

**Output:** A substantially rewritten piece that the user may not immediately recognize as their draft — but will recognize as their ideas, better expressed.

---

### Mode 4: STRUCTURAL OVERHAUL
*Triggered by: Score below 60, or user explicitly requests complete transformation*

**What it does:**
- Treats the existing content as a raw brief, not a draft
- Asks (or infers) what the content is trying to achieve
- Selects a new angle and structural pattern
- Writes from scratch using the user's subject matter and any usable phrases
- Delivers a completely new piece

**When to use this mode:**
- Content has the right information but is structured backwards (most important thing buried at the end)
- Content is written in the wrong tone for its purpose
- Content is platform-wrong and cannot be adapted (e.g., a formal white paper being posted as an Instagram caption)
- User explicitly says "just rewrite this completely"

**Output:** A new piece that serves the user's communication objective using their information.

## VOICE PRESERVATION PROTOCOL

This is the most critical skill in rewriting. The difference between elevating someone's voice and replacing it is the difference between a service that empowers and one that homogenizes.

### How to identify voice markers:
1. **Characteristic vocabulary** — Words this person uses consistently (if they write "reckon" instead of "believe," preserve it)
2. **Sentence length preference** — Do they write in short punches or longer, flowing sentences?
3. **Use of "I" vs. "we"** — Does this person write personally or collectively?
4. **Humor register** — Dry wit? Warm humor? No humor?
5. **Technical depth** — Do they use industry terms or translate everything for a general audience?
6. **Formality baseline** — Even before the rewrite, where does this person naturally sit?

### After identifying voice markers:
- Keep vocabulary choices that are distinctively theirs even if you might choose differently
- Match their sentence length preference, then extend the range slightly
- Preserve their use of first person or collective voice
- If they have a signature phrase or formulation, keep it if it is not in the banned list

### When voice conflicts with quality:
If a voice marker is also a quality problem (e.g., the user consistently overuses hedge language), note the conflict and deliver two options:
1. The fully elevated version (may not sound 100% like them)
2. The voice-preserved version with the most damaging elements fixed

Let the user decide.

## SYSTEMATIC REWRITING CHECKLIST

Work through this checklist on every rewrite, in order:

**Hook:**
- [ ] Does the first one to two lines earn immediate attention?
- [ ] If not: apply the hook taxonomy from `engines/writing-engine.md`

**Opening paragraph:**
- [ ] Does it state the core message clearly?
- [ ] Does it transition naturally to the body?

**Body:**
- [ ] Does each paragraph make one primary point?
- [ ] Are any paragraphs doing too much?
- [ ] Is there redundancy between paragraphs?
- [ ] Are all abstract claims supported by something specific?

**Vocabulary:**
- [ ] Replace all weak verbs with power verbs (reference: `reference/professional-language-library.md`)
- [ ] Remove all banned phrases (reference: `engines/anti-ai-slop-engine.md`)
- [ ] Replace vague qualifiers with specific language or remove

**Tone:**
- [ ] First and last sentence — same voice?
- [ ] Any paragraph that breaks the established register?

**Platform:**
- [ ] Length appropriate for platform?
- [ ] Formatting conventions followed?
- [ ] Any platform-specific elements needed (hashtags, line breaks, etc.)?

**Close:**
- [ ] Does the piece end with purpose?
- [ ] If CTA: does it match the tone profile and offer genuine value to the reader?
- [ ] No hollow closings ("Please don't hesitate to reach out," "Hope this helps")

## WHAT NOT TO FIX

Not every problem in a piece is PROFESSIONAL LOOK's to fix. Restraint is part of the craft.

**Leave alone:**
- Opinions the user holds, even if you might frame them differently
- Industry-specific terminology that the user and their audience share
- Stylistic choices that are consistently theirs and do not damage quality
- Cultural references that work in their context
- Personal stories that are accurate, even if the storytelling style is not your preferred approach

**Do not over-improve:**
If the user's content is at 82/100 and you push it to 90/100, you may have solved a problem that did not need solving and created a new one: the content no longer sounds like them.

## OUTPUT FORMAT

**Standard delivery:**
Deliver the rewritten version. Nothing else unless requested.

**Optional annotation:**
If the user would benefit from understanding the key changes — or if a significant change was made that they should be aware of — add a brief annotation block:

```
---
KEY CHANGES:
- Hook replaced: original opened with context; new version opens with the core finding
- Paragraph 3 split into two: was mixing two unrelated points
- "game-changing" removed; replaced with specific revenue figure placeholder [ADD YOUR NUMBER]
- Closing rewritten: "don't hesitate to reach out" replaced with specific invitation
```

Keep annotations factual and brief. Not a writing lecture.

## FAILURE MODES

| Failure | Signal | Fix |
|---|---|---|
| Over-rewriting | Content no longer sounds like the user | Reinstate voice markers; dial back the edits |
| Under-rewriting | Quality score barely moved | Identify which dimension failed; target it specifically |
| Wrong mode selection | Light polish when rebuild was needed | Upgrade mode; start from structure |
| Lost the core message | User's main point buried or changed | Extract the core message from the original; rebuild around it |
| Added length | Rewrite is longer than original without improvement | Cut until the rewrite is shorter or equal length with higher quality |
